## Run locally

The tool runs on `@eupadev/core` (exact version in `package.json`, from
the forge's npm registry): the core is the server. It reads `openapi.yaml`,
loads one handler per operation from `api/`, serves `web/`, and needs its
PostgreSQL database and the identity provider. The reference tool is
`examples/requests` in the EupaDev repository.

```sh
pnpm install
node node_modules/@eupadev/core/bin/start.js --verify     # contract and handlers, no database
pnpm test                                                        # unit tests (node --test)
```

## CI and delivery

Every push runs `.gitea/workflows/check.yml`: secret scan, tests, static
analysis, guard rails, image build with the platform's fixed
`.gitea/image/Dockerfile` (not editable) from the EupaDev golden image,
vulnerability scan, then the image is started read-only with a throwaway
database (migration by the same image) and probed on `/health`.
On `main` only, that same image is published to the forge registry and its digest recorded: Preview
and Production receive this exact digest, nothing is rebuilt.
`preview-check.yml` runs performance, accessibility and dynamic security
checks, and the tool's acceptance suite with the platform's SEC-* checks,
against the deployed Preview; the orchestrator starts it.
